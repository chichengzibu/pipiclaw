## 2. 3 个子项目独立分解

### 子项目 A:5 个 demo 真实环境验证
**目标**:把 D1/D2-Prime/D3/D5/A5 5 个 demo 在真实用户环境跑通,截图归档

**依赖清单**:
- macOS/Windows/Linux 用户机 ×1 台
- 屏幕访问权限(Electron 已给,首次需用户授权)
- Node 20+ 已装
- npm install 跑过(目前主会话未装 `@webcontainer/api`,需 `npm install`)

**风险**:
- D1/D5 需要桌面录屏,首次需用户授权 + 屏幕内容(可能含敏感信息)
- D2-Prime 走 WebContainer / docker 二选一,W11 阶段都 stub
- A5 走 AgentBrain,W11 阶段 stub 简单决策
- D3 走 CalendarConnector 假日程,需 fake 飞书环境

**验证步骤**(5 demo 各 5-10 步):
- D1:启动 → 全局快捷键 Cmd+Shift+S → 截屏 → 提问 → 看 AgentBrain 返回
- D2-Prime:打开 `/d2-prime-demo` → 输入"做博客" → 看 SandboxBuilder 选 vite-react-ts → 写文件 → 看 stub 预览
- D3:配飞书账号(子项目 B)→ 飞书发"今天日程" → 看 ChannelRouter 路由 → AgentBrain 解析 → CalendarConnector 假数据 → 飞书回复
- D5:启动 → 开始录屏 → 录 30s → 停止 → 看 SKILL.md stub 生成
- A5:打开 `/a5-demo` → 输入"打开浏览器" → 截屏 stub → 看决策循环

### 子项目 B:真实 IM 账号接入(飞书/钉钉/企微)
**目标**:把 3 个真接 IM 通道用真实 appId/secret 跑通,真实收发消息

**依赖清单**:
- **飞书**:appId + appSecret(https://open.feishu.cn/ 创建企业自建应用)
- **钉钉**:appKey + appSecret + Robot webhook(https://open-dev.dingtalk.com/)
- **企微**:corpId + corpSecret(https://work.weixin.qq.com/wework_admin/)
- **公网回调 URL**:3 个 IM 平台都需要(`https://your-domain/im/webhook/feishu` 等),需内网穿透(ngrok / frp)或公网服务器
- **白名单 IP**:3 个 IM 平台需把回调地址的 IP 加白名单

**风险**:
- 飞书/钉钉/企微 平台审核:个人开发者账号只能创建测试应用,不能发群消息
- 公网回调 URL:无域名时需内网穿透,ngrok 免费版限速
- 鉴权失败:appId/secret 错误率较高,需仔细按平台文档配置
- 频率限制:发消息有 QPS 限制(飞书 50 QPS,钉钉 100 QPS)

**配置位置**:
- 3 个通道的鉴权信息存到 `userData/im-config.json`(W7.2 IMConfigStore)
- UI 入口:可加一个 IM 账号配置 view(`/settings/im-accounts`),但当前未建

**验证步骤**:
1. 注册平台开发者账号 → 创建应用 → 拿 appId/secret
2. 配置 WebSocket / Webhook 回调 URL(ngrok 内网穿透到本机)
3. 在 UI 填入配置 → IMConfigStore 持久化
4. 飞书发"hi" → 看 ChannelRouter.receive → AgentBrain.parse → ChannelRouter.send 回复

### 子项目 C:docker 沙盒链路验证
**目标**:把 W9-W10 sandbox 全链路在真 docker 环境跑通,验证 sandbox:selfcheck 5/5 过

**依赖清单**:
- **Docker 24+** 已装且 daemon 跑
- **bubblewrap** (Linux only,`apt install bubblewrap`)
- **磁盘空间** ≥10GB(base 镜像)
- **网络访问**:`registry.npmmirror.com` / `pypi.tuna.tsinghua.edu.cn` / `goproxy.cn` / `maven.aliyun.com` + AI API 域名

**风险**:
- macOS Docker Desktop 资源限制:默认 4GB RAM / 2 CPU,W10.2 默认 4GB/2CPU 够用
- Linux bwrap 需 root 或 setuid 安装
- base 镜像首次 build 慢(15-30 分钟),需稳定网络
- 端口冲突:4000 起递增,W11.2 实现已处理

**验证步骤**:
1. `node scripts/sandbox-selfcheck.mjs` → 看 5 检查结果
2. `node scripts/sandbox-base-build.mjs --run` → build base 镜像
3. `node scripts/sandbox-base-build.mjs` → 验证 dry-run 输出
4. 手动跑 `docker run -v /tmp/test:/mnt/data -it pipiclaw/sandbox-base:latest bash` → 进容器看 ubuntu 24.04 + 4 语言
5. 用 SandboxBuilder 选 vite-react-ts 模板 → 写文件 → 看 hostPath 有文件
6. (进阶)PortForwarder.forwardPort(5173, workspaceId) → 端口分配 → 看能否 curl http://localhost:4000(虽然容器没跑)
7. (进阶)SandboxL1.run(['echo', 'hello'], { mode: 'seatbelt' }) → macOS 沙箱跑命令 → 看返回
8. (进阶)SandboxLifecycle.start() → 等 30 分钟看 idle stop(W11 stub)
