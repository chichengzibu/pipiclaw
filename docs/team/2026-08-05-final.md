## 3. Top 3 风险 (跨 3 报告综合)

### 🔴 #1: forceResetToPermissive 修法"够用不彻底" — 分歧点

**backend 修法** (backend §3.4, commit `feec4a1`):
```ts
// PermissionConfig.ts:286-335
public forceResetToPermissive(options?: { force?: boolean }): boolean {
  const force = options?.force === true;
  const isDevMode = process.env.PIPICLAW_DEV === '1';
  const isExplicitReset = process.env.PIPICLAW_RESET_PERMISSIONS === '1';
  const isFirstBoot = !this.activeSetId;
  if (!force && !isDevMode && !isExplicitReset && !isFirstBoot) {
    this.log.info('跳过强制重置 (生产模式 + 已设过权限)');
    return false;
  }
  // ... 重置逻辑
}
```

**architect 立场** (architect §1.4):
- 修法方向对但**修法太轻**
- "问题不在'怎么开关',在'为什么存在这个函数'"
- 必须: ① 删 `forceResetToPermissive` 调用 (main.ts:86) ② 保留函数作 migration 工具,带 version check ③ 加"持久化当前模式"开关 ④ **首次安装默认 `safe`** 而非 `permissive` ⑤ 改命名 "无限制模式" + 红字警告 ⑥ 模式切换进 audit log

**核心分歧**:
| 维度 | backend 当前 | architect 理想 | CFO 判断 |
|---|---|---|---|
| **函数调用** | 仍每次启动调用 (但首次/已设/env 除外) | 删调用, 只 migration 触发 | backend 满足"尊重用户",architect 想要"默认即正确" |
| **首次启动** | 仍重置为 permissive | 默认 safe | **architect 对** — 安全默认值 = 最小权限 |
| **命名** | 仍是 "preset_permissive" (含义模糊) | 改 "无限制模式" + 红字 | **architect 对** — UX 防呆 |
| **audit log** | 没有 | 模式切换进 EventBus + Insight | **architect 对** — 可观测性 |

**CFO 立场**: backend 的修法是"补丁式有效":
- 首次启动 → activeSetId 空 → 走 first boot 分支 → 重置为 permissive (新用户体验无摩擦)
- 后续启动 → 已设 → 跳过 reset → 用户选择被尊重 ✅
- 升级用户从 v4.3 升 v4.3.1 → 旧 permissions.json 读到 activeSetId → 走"已设"分支 → 保留旧选择 ✅

**但** architect 担忧的"active 漏洞"层面:**用户装 v4.3.1 首次启动,默认就是 permissive (无任何防护)** — 这跟 v4.3.0 之前的"未修状态"差异不大。**安全默认值是 safe** 才是行业标准。

**风险等级**: 🟠 Major (不阻塞 dogfooding,阻塞 public release)
**修法**: 见 P0-1 清单

### 🔴 #2: LlmClient 副作用致 5 vitest 回归 + d5:run bug 挡 SkillSigner e2e

**含义**: SkillSigner 修对了 (源码 `loadOrCreateKey` + `safeStorage.encryptString` + `randomBytes(32)` 全在, backend §3.5),**只是没被 instantiate**。修 d5:run bug → SkillSigner 自然 instantiate → e2e 自动 pass。

**风险等级**:

## 6. CONDITIONAL 必修复清单 (按优先级)

### P0 阻塞公开 (9 项)

#### [P0-1] forceResetToPermissive 深度重做 (2-3 天)
**问题**: backend §3.4 修法只加 env 开关, 仍每次启动调用 + 默认 permissive + 命名误导 (architect §1.4)
**修法** (architect §1.4):
1. **删 `forceResetToPermissive` 调用** (`main.ts:86` 移除)
2. **保留函数作为 migration 工具** — 只在版本升级 + 旧 config 格式不匹配时调用一次,带 version check
3. **首次安装默认 `safe` 模式** — 不是 `permissive`
4. **改命名 "preset_permissive" → "preset_unrestricted"** + UI 红字警告 "不推荐"
5. **加 Settings 开关 "记住权限模式"** + 模式切换进 EventBus + Insight audit
6. **e2e**: 加 spec 验证 "用户选 safe → 重启 → 仍 safe" + "首次安装 → safe 不是 permissive"

#### [P0-2] HMAC 升 Ed25519 + TOFU 信任 (3 天)
**问题**: backend §3.5 仍 HMAC 对称 + Linux fallback base64 明文 (architect §1.5)
**修法** (architect §1.5):
1. `crypto.generateKeyPairSync('ed25519')` → 私钥 `safeStorage.encryptString` → 落盘 `userData/keys/skill-signer.priv`
2. 公钥明文落盘 `userData/keys/skill-signer.pub`
3. **第三方 skill 公钥 TOFU 信任** — 首次导入弹"信任此开发者" + 记录到 `trusted-skills.json`
4. **签名覆盖 manifest + deps** (不只是 skill.md)
5. **签名带 `signedAt` + `expiresAt`**,verify 检查有效期
6. **Linux fallback 拒绝启动** (除非 `PIPICLAW_DEV=1`): `if (!safeStorage.isEncryptionAvailable() && !process.env.PIPICLAW_DEV) throw '无法安全存储签名密钥,拒绝启动'`

#### [P0-3] LlmClient ollama 副作用修复 (1-2 天)
**问题**: qa §4.1 vitest 902 → 897 (-5),`ollama-real-link.test.ts` 5/6 fail (S1-S4 + S6)
**修法**:
1. 跑 `ollama-real-link.test.ts` 6/6 pass = baseline
2. git bisect backend LlmClient 改动 (5 commit 内)
3. 修 OpenAI adapter 流式 / 错误处理 不破坏 ollama 兼容路径
4. 加 e2e: 跑 user-journey-ollama 31/31 + ollama-real-link 6/6 (双向验证)

#### [P0-4] d5:run builtin bug 修复 (0.5 天)
**问题**: qa §3.5 `d5:run` 内部 `require('../skill/builtin/D5RecordingToSkill')` 在 bundled `dist-electron/main.js` fail (`Cannot find module`)
**修法**:
1. electron-builder 配置把 `electron/skill/builtin/D5RecordingToSkill.ts` bundle 进 main.js
2. 跑 `p0-security-signer.spec.ts` 2/2 pass
3. 加 e2e: 用户跑 d5 → SkillSigner instantiate → key file 落盘 → safeStorage 加密

#### [P0-5] file path 沙箱 (1-2 天)
**问题**: backend §5.1.1 `FileOperationParams.path` 走 `resolvePath()` 不限制范围
**修法**:

**修法**:

#### [P0-7] SkillLoader 强制 verify 启用 (1 天, 依赖 P0-2)

3. 加 Settings 按钮 "重新签名所有 skill"
