## 一段总结

实现 MCP 2025-06-18 协议子集 (JSON-RPC 2.0 over stdio, 3 类消息 + 4 个核心 method),新增 5 个 TS 模块 + 1 个独立 .mjs 子进程 + 8 个 IPC 通道。filesystem server 提供 5 个工具 (list_directory / read_file / write_file / search_files / get_file_info),全部走路径沙箱白名单,子进程 stdout 严格 newline-delimited JSON-RPC,父进程维护 id→pending 映射 + 串行化写。PoC 跑通: spawn → initialize → tools/list=5 → 5 个工具全部真调用成功 → 路径沙箱越界拒绝 → 优雅 stop。集成到 main.ts 启动时自动 load enabled servers, IpcServer 暴露 8 个新通道 (start-server / stop-server / start-all-enabled / stop-all / list-servers / list-tools / list-tools-by-server / invoke), preload 已 contextBridge 出去。

## 关键设计决定

1. **位置**: `electron/mcp/` 而非 spec 写的 `src/mcp/` — 这代码必须跑在主进程 (spawn 子进程), `src/` 是 Vue renderer。build 时 McpManager 被打进 main.js (vite-plugin-electron 已有),filesystem-server.mjs 由新加的 `copyMcpBinPlugin` 复制到 dist-electron/mcp/bin/。
2. **子进程 Node 选择**: 走 `process.execPath` + `ELECTRON_RUN_AS_NODE=1` (prod),回退 `node` (dev/standalone),这样打包后不依赖系统装 node。
3. **JSON-RPC 严格性**: 写串行化 (writeQueue),读走 buffer + indexOf '\n' 防半行; 启动时必走 initialize → 等 capabilities 返回才标 ready; 失败/超时 reject 所有 pending。
4. **路径沙箱**: 2 道闸 — transport 接受 allowedPaths 数组,server 在 `resolveInSandbox()` 用 `realpathSync` 解析 symlink 后 lowercase prefix 比对; 拒绝 '..' / null byte / sandbox 外。

## 与 spec 偏差 (透明)

1. **位置**: 用了 `electron/mcp/` 不是 `src/mcp/`。理由: spawn 子进程 + IPC handler 都在主进程, 跟随项目现有 `electron/openclaw/ electron/llm/ electron/hermes/` 模式。
2. **不实现 zod**: spec 提到"用 zod 校验",本任务没加 zod 依赖 (避免 npm install 镜像 + PoC 阶段过度工程), 改用 MCP `inputSchema.required` 字段做基础必填校验。 完整 schema 校验 (类型 / enum / pattern) 留 M2 + zod 引入。
3. **不带 UI 截图**: PoC 是 CLI 跑 14 测试, 不启动 electron GUI。 完整 UI 截图 (Settings.vue → MCP 配置 → 工具列表) 等 M2 UI 集成时再补。
