## 3. 5 个新 e2e spec 覆盖度

5 个 spec 放 `tests/e2e/p0-security-*.spec.ts` + `_p0-helpers.ts` 共享 utilities。

**通用设计**:
- 启动 fresh Electron (用 `mkdtempSync` 生成 userData, 隔离跨 spec)
- env `PIPICLAW_E2E=1` 强制 WindowManager 走 prod 路径 (loadFile dist/index.html)
- 启动后探测 OpenClawServer 真实端口 (18789 可能被 svchost/iphlpsvc 占, fallback 到 18790+)
- 用 `node:http` 直接测 (避开 renderer webSecurity + CORS 限制)
- 通过 `win.evaluate` 调 IPC (renderer 进程)

### 3.1 p0-security-cors.spec.ts (覆盖 C2: CORS 收口)

| Test | 期望 | 实测 | 状态 |
|---|---|---|---|
| GET /health 同源应 200 | 200 | 200 | ✅ |
| GET /health + Origin evil.com | ACAO ≠ `*` (改前 `*`, 改后拒绝 403) | ACAO=null, status=403 (CORS_DENIED) | ✅ |
| OPTIONS 跨域预检 | 不应 200+ACAO=`*` | 403 | ✅ |
| POST /execute 不带 token | 401/403 (CORS 收口后还能拿到拒绝) | 403 (CORS_DENIED 优先) | ✅ |

**3/3 PASS** (412ms 总耗时)

覆盖: `Access-Control-Allow-Origin` 不再 `*`, 跨域 origin 默认拒绝, OPTIONS 预检收口。

### 3.2 p0-security-token.spec.ts (覆盖 C2: token 鉴权)

| Test | 期望 | 实测 | 状态 |
|---|---|---|---|
| 无 token POST /execute 应 401 UNAUTHORIZED | 401 + errorCode=UNAUTHORIZED | 401, errorCode=UNAUTHORIZED | ✅ |
| 有 token POST /execute 应 200 (IPC 暴露 token 时跑) | 200/500 | **skip** (token IPC 未在 preload 暴露) | ⏭️ skip |
| 错误 token POST /execute 应 401 | 401 | **skip** (token IPC 未暴露) | ⏭️ skip |

**1/1 PASS, 2 SKIP** — 核心断言 (无 token 401) 通过; "有 token 200" 和 "错误 token 401" 跳过了, 因为 backend `gateway:auth-token` IPC 没在 preload 包装。

**改进建议**: backend 应在 `electron/preload.ts` 加 `gateway: { getAuthToken: () => ipcRenderer.invoke('gateway:auth-token') }`, 之后 spec 自动能跑。

### 3.3 p0-security-injection.spec.ts (覆盖 C1: runCommand 注入防护)

通过 IPC `openclaw:execute` 直接调 `OpenClawGateway.runCommand` (不走 HTTP /execute, 避开 token 鉴权; 也不走 task:execute, 因为 TaskExecutor **会丢 args**, 不能测 args null byte 检查)。

| Test | 期望 | 实测 | 状态 |
|---|---|---|---|
| runCommand 含 shell metachar (`;`) 应被拒 | 拒绝 (server 明确错误信息) | "runCommand: command 含非法字符,只接受 baseCmd: echo safe..." | ✅ |
| runCommand 不在白名单 (`nc`) 应被拒 | 拒绝 | "runCommand: 不在白名单的命令 'nc',允许列表见 COMMAND_ALLOWLIST" | ✅ |
| runCommand 含 null byte 参数应被拒 | 拒绝 | "runCommand: args[0] 含 null byte" | ✅ |

**3/3 PASS** (76ms 总耗时)

**注**: `COMMAND_ALLOWLIST` 实际包含 `git/node/python/curl/wget/powershell/cmd/bash/...` (40+ 命令), 但 `python`/`curl` 都在白名单, 所以 spec 故意用 `nc` (绝对不在白名单) 测拦截路径。

**额外发现** ⚠️: `TaskExecutor.executeTask` 调 `run_command` 时**不传 args** (line 187-190 `command + cwd` 丢 `args`)! 这意味着即使 backend runCommand 修了 args 检查, 通过 `task:execute` 路径仍然丢 args。这是**不在 P0 范围**的 bug, 但应单独 fix。

### 3.4 p0-security-permission.spec.ts (覆盖 C3: forceResetToPermissive env 控制)

**3 个 test 启动 2 次 Electron 共享 userData**, 验证 startup 行为:

| Test | 流程 | 期望 | 实测 | 状态 |
|---|---|---|---|---|
| A. fresh + 不设 env | 首次启动 | active=permissive (first boot reset) | active.template=permissive | ✅ |
| B. 重启 + 不设 env | run1 setActive safe → run2 启动 | 跳过 reset, active 保持 safe | active.template=safe | ✅ |
| C. 重启 + PIPICLAW_DEV=1 | run1 setActive safe → run2 启动 + env | 强制 reset, active=permissive | active.template=permissive | ✅ |

**3/3 PASS** (9s 总耗时)

覆盖: `forceResetToPermissive(options)` 接受 `options.force` + 检查 `PIPICLAW_DEV=1` / `PIPICLAW_RESET_PERMISSIONS=1`, 满足任一才真重置; 否则尊重用户上次选择。

**注意事项**:
- spec 启动时必须传 `--user-data-dir=` (放在 `mainEntry` 之前), 否则 Electron 用 default `C:\Users\Administrator\AppData\Roaming`
- 第一次启动后 `setActive` 持久化到 `permissions.json`, 第二次启动读到 → 验证持久化 + force reset 行为
- 这是测 startup 行为, **必须真实启动两次**才能验证

### 3.5 p0-security-signer.spec.ts (覆盖 C4: SkillSigner safeStorage)

| Test | 期望 | 实测 | 状态 |
|---|---|---|---|
| userData/skill-signer-key.json 应存在 (改前不会有) | 存在 + safeStorage 加密 base64 | **file 不存在** | ❌ FAIL |
| 两个 fresh userData 启动, key 应不同 | k1 ≠ k2 | **k1=null, k2=null** | ❌ FAIL |

**0/2 PASS, 2 FAIL** — 不是 backend SkillSigner 修复有错, 而是 **d5:run IPC require bug 间接导致测试失败**:

- spec 触发 `d5:run` IPC 试图间接触发 `runD5 → AutoCreator → SkillSigner.getInstance() → loadOrCreateKey 写文件`
- 但 `d5:run` 内部 `require('../skill/builtin/D5RecordingToSkill')` 在 bundled `dist-electron/main.js` 里 **fail** (`Cannot find module`)
- `runD5` 拿不到 → `AutoCreator` 没 instantiate → `SkillSigner` 没 instantiate → `loadOrCreateKey` 没跑 → key 文件**没写**
- 实际上 SkillSigner 本身**已正确实现** (源码里 `loadOrCreateKey` + `safeStorage.encryptString` + `randomBytes(32)` 全在), 只是没被 instantiate

**这是 backend 第 6 个洞**: D5RecordingToSkill 没 bundle 进 main.js, require 失败。修 d5:run 之后 spec 应该自动 pass (因为 SkillSigner.getInstance() 会在 d5:run handler 触发时跑, 写 key file)。

**不影响 P0 安全洞本身 (SkillSigner fix 正确), 是 e2e 验证机制被另一个 bug 挡住**。
