# PiPiClaw UI/UX 方案 v1.0 · Owner 自评

> **作者**: Mavis
> **视角**: 作为方案作者 + PiPiClaw owner,对自己写的方案做不留情面的复盘
> **原则**: 自评要狠,找问题比夸自己重要

## 综合评分: 7.5 / 10

一句话: **原则立得住,token 拿得出手,但具体组件/动效深度不够,实施路线偏理想化,缺可落地的"前 5 个 commit 该改什么"。**

---

## 做得好的（🟢 亮点）

### 1. 设计原则有取舍（5 条够了,不多不少）
- 5 条原则互相不冲突,密度/节奏/克制/token/键盘,站位一致
- 没有"既要信息丰富又要简洁"这种自打脸
- **值得保留**: 这套原则可以进 brand guidelines,作为后续设计决策的裁判

### 2. Token 系统是真正的"系统",不是"罗列"
- 8 档 spacing / 8 档字号 / 4 档 radius / 4 档 motion,有层级有命名
- 颜色 light + dark 两套足够,不做 3+ 套决策疲劳
- 黄金比例 1.125 算过,不是随手
- **真正可落地**: 给 coder 一份 CSS 变量表,就能写组件

### 3. 反例明确（第 11 节）
- 把"不做的事"明写出来,这是工程纪律
- 弹性动画 / 彩虹渐变 / 5+ 主题 / slide 路由 全部说"不"
- **省下未来的争论**: 有人想加 3D 翻页?反例清单拍他脸上

### 4. 加载 4 模式分类正确
- spinner / skeleton / progress / stream,覆盖了 AI app 所有场景
- 各自的适用时长和样例都对得上
- **不会有"用菊花做长任务"这种廉价感**

### 5. 命令面板给了 keyboard 细节
- ↑↓ Enter Tab Esc,具体可实现
- 200ms scale + opacity,克制不浮夸
- **不是"做个 Cmd+K"这种空话**

---

## 做得不够的（🟡 升级点）

### 1. **微交互的"为什么"写得不够** 🟡
- 11 项微交互列了,但没说**每个的具体触发场景**
- 比如「列表 stagger」——是在 Chat 消息列表?Skill 列表?命令面板结果?
- 缺: 11 项 × N 个场景的触发矩阵
- **建议补**: 第 4.1 节后加一张表,列哪个组件用哪几个交互

### 2. **路由切换的"为什么 0ms"没说清** 🟡
- "Linear 路线,工程师 app 不需要华丽"——这不是理由,是判断
- 缺用户调研或对照数据:Linear 是 0ms 吗?Cursor 是 0ms 吗?我查了文档但没引用
- **建议补**: 加一句"Linear 路由切换实测 0ms 瞬时,Raycast 50ms fade,Cursor 80ms"

### 3. **实施路线过于理想化** 🟡
- 12 个 commit / 3 周,听上去美好
- 没考虑现状:当前 PiPiClaw 有 4 个 theme 配置,改 token 要兼容旧
- 没考虑"先改哪个组件能立刻看到效果"
- **建议补**: 把 12 个 commit 重排为"第 1 周 ship, 后面渐进"——5 个 commit 的 MVP,后 7 个增量

### 4. **暗色模式"重新调色"不具体** 🟡
- 说了"不是简单 invert",但具体规则没说
- 比如:`--bg-primary` 浅色 `#ffffff` → 深色 `#1e1e1e`,差 32 个亮度,符合"压暗而不反相"吗?
- 缺: light/dark 颜色对应表 + 调色规则(背景压暗 80%,文字压暗 30%?)
- **建议补**: 第 7 节加 "Light → Dark 调色公式"

### 5. **空状态文案没写** 🟡
- 第 6.2 节说"大图标 + 标题 + quick prompt 卡片",但文案呢?
- Chat 空状态:标题写什么?quick prompt 给哪 3 个?
- Skills 空状态:"还没有技能,去 ClawHub 看看" 还是 "从模板市场一键安装"?
- **建议补**: 加一节"空状态文案库",每个页面 3 个候选

### 6. **错误状态没单独成节** 🟡
- 第 6.5 提到表单错误,但全局错误(网络断/服务挂/权限拒)没写
- 缺:错误状态设计 = "什么错" + "怎么提示" + "用户能做什么"
- **建议补**: 加一节"Error States",至少 5 种典型错误

### 7. **性能预算不具体** 🟡
- 说了 LCP < 1.5s,但没说**怎么达到**
- 动画只用 transform/opacity,缺:**bundle 拆包 / 图片懒加载 / CSS 优先级** 这些工程手段
- **建议补**: 第 10 节加工程手段,不止"目标数字"

### 8. **无障碍只到 WCAG AA** 🟡
- 大部分 app 只到 AA,够用
- 但**没考虑**屏幕阅读器用户的具体体验:Toast 怎么朗读?命令面板的搜索结果怎么朗读?
- **建议补**: 加一节"屏幕阅读器友好",至少 3 个具体场景

## 真正的硬伤（🔴 必须改）

### 1. **没说明"现状诊断 → 目标状态"差距** 🔴
- 这方案是从 0 写的,不是从现状改造的
- 缺: 当前 PiPiClaw 的具体痛点 → 方案如何解决
- 比如:"现在 ChatSidebar 标题 18px、按钮 32px 圆角 4px,改为 13px / 28px / 圆角 4px" 这样的对照
- **修补方向**: 第 0 节加 "现状 vs 目标" 对照表,至少 10 个具体改造点

### 2. **没考虑 Element Plus 兼容性** 🔴
- PiPiClaw 用 Element Plus + unplugin-vue-components
- 我们的 token 怎么覆盖 EP 的内置组件?el-button 的 padding 是 12px 20px,跟我们的 36px 按钮不一致
- 缺: Element Plus 主题覆盖策略
- **修补方向**: 第 9 节实施前,先加一节 "Element Plus 主题统一"

### 3. **暗色模式没考虑 OpenClawGateway 状态色** 🔴
- PiPiClaw 是 AI 工具,有"思考中" / "执行中" / "已就绪" 等状态色
- 这套状态色在暗色模式下要不要变?比如 success 在 light 是 `#10b981`,暗色是 `#34d399` —— 能不能让用户一眼分清?
- 缺: 状态色的 light/dark 调色规则
- **修补方向**: 第 2.3 节加 status 颜色,且 light/dark 保持 4.5:1 对比度

### 4. **缺"如何不破坏现有功能"的回退策略** 🔴
- 12 个 commit 改的是设计系统,不是加新功能
- 如果 Button 组件重写导致全站 30 个按钮出问题怎么办?
- 缺: 灰度发布 / 单组件回滚 / 旧 API 兼容 期
- **修补方向**: 第 9 节加 "风险与回退",每个 commit 标风险等级

### 5. **度量指标不能验证** 🔴
- 第 10 节说"组件审查 0 偏差",但谁来审查?用什么工具?
- "命令面板打开 < 200ms (P90)" 怎么测?Playwright?
- 缺: 每个指标的**具体测量方法**
- **修补方向**: 第 10 节每条加 "如何验证"

## 总结

**方案立意对了**: 5 原则 + token 系统 + 4 加载模式 + 11 微交互,这套组合拳方向正确。

**深度还不够**: 缺现状对比、缺 EP 兼容、缺错误状态、缺测量方法、缺风险评估。

**适不适合现在 ship 给团队执行**: 不适合。需要补 5 项 P0 才能进开发。

**适不适合作为 v1.0 草稿讨论**: 适合,但下一轮必须把"现在 → 未来"对照说清楚。
